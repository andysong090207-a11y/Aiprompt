# 지하철 도착 예측 (Android, 오프라인)

인터넷 없이 동작하는 안드로이드 지하철 앱입니다.

- **역 도착 정보판**: 노선과 역을 고르면 방향별로 "인천행 3분 12초" 처럼 다음 열차가 몇 분 몇 초 후에 오는지 보여 줍니다. 5초 이하로 남으면 빨간 글씨로 바뀝니다.
- **즐겨찾기**: 자주 쓰는 역을 저장해 첫 화면에서 바로 다음 열차를 봅니다(편집에서 순서 변경·삭제).
- **탑승 후 추적**: 폰 센서로 열차의 출발과 정차를 감지하고, **기지국 ID와 Wi-Fi 스캔 목록**으로 현재 역을 보정해 다음 역(또는 하차역) 도착 시각을 **초 단위**로 예측합니다.
Samsung Galaxy S26(Android 16)을 기준으로 만들었고, **기압계는 쓰지 않습니다**.

## 동작 방식

```
가속도계 ─┐
자기장   ─┼─▶ 출발/정차 감지 ─▶ 현재 역 추적 ─▶ 초 단위 예측 ─▶ 화면 / 알림 / 진동
자이로   ─┤   (MotionClassifier)  (TripTracker)    (Predictor)
걸음감지 ─┘                            ▲  │
     GPS(지상 구간만) ────────────────┤  └─▶ 구간·정차 시간 학습 (TravelStats) ─▶ 역 도착 정보판
     기지국·Wi-Fi 스캔 ───────────────┘       역별 무선 신호 학습 (RadioFingerprints)
```

| 단계 | 내용 |
|---|---|
| 센서 | 가속도계, 자기장 센서, 자이로 50Hz, 걸음 감지기. 기압계는 쓰지 않음 |
| 출발/정차 감지 | 1초 창마다 **진동 세기**(바퀴·레일 진동), **자기장 변동**(전동차 모터), **지속 가속도**(출발·제동)를 계산합니다. 폰을 손에 들었는지 주머니에 넣었는지에 따라 달라지는 잡음 바닥은 최근 10분 기록에서 자동으로 추정합니다. 걷는 중이거나 폰을 돌릴 때는 판단하지 않습니다 |
| 초 단위 시각 | 상태가 바뀐 것을 확정한 뒤, 그 변화가 **처음 시작된 창의 시각으로 거슬러 올라가** 기록합니다(오차 ±1초 이내, 합성 신호 테스트 기준) |
| 역 추적 | 정차가 감지되면 달린 시간을 예상 시간과 비교합니다. 너무 이르면 **신호 대기**로 보고, 한참 늦으면 **정차를 놓친 것**으로 보고 두세 정거장을 건너뜁니다 |
| 예측 | `도착 시각 = 실제 출발 시각 + 신호 대기 시간 + 학습된 구간 주행 시간`, 이후 역은 `+ 학습된 정차 시간 + 다음 구간 시간`을 이어 붙입니다. 불확실성(±초)도 같이 계산합니다 |
| 학습 | 정상적으로 측정된 구간 주행 시간과 정차 시간을 지수가중 이동평균으로 학습합니다. **출퇴근 시간(평일 7–9시, 18–20시)과 그 외 시간을 따로** 학습하고 폰에만 저장합니다 |
| GPS | 시작 후 1분 동안과 **지상(고가) 구간**에서만 켭니다. 멈춰 있을 때 역 반경 안에 있으면 현재 역을 보정합니다. 그 외에는 다른 앱이 받아 둔 위치(passive)만 씁니다 |
| 기지국·Wi-Fi | 탑승 중 10초마다 주변 기지국 ID(LTE/5G 셀 ID, 없으면 주파수+PCI)와 Wi-Fi 목록(BSSID, SSID)을 읽습니다. 정차 중이면 그 역의 "신호 지문"으로 학습하고, 다음 이동부터는 앞뒤 역 중 신호가 훨씬 더 닮은 역이 **두 번 연속** 나오면 그 역으로 보정합니다. 여러 역에서 공통으로 보이는 신호(통신사 공용 Wi-Fi 등)는 가중치를 낮춥니다. SSID에 역 이름이 들어 있으면(예: `GS25_강남역점`) 학습 전에도 근거로 씁니다 |
| 도착 정보판 | 노선 파일의 **운행 패턴**(첫차, 막차, 시간대별 배차 간격)과 학습된 구간·정차 시간으로 각 열차가 그 역에 언제 오는지 계산합니다. 실시간 위치가 아닌 **추정치**입니다. 새벽 4시를 하루의 경계로 보고, 막차 후에는 다음 날 첫차를 보여 줍니다 |
| 알림 | 하차역(탑승 화면에서 역을 눌러 지정) 직전 역을 출발하면 진동과 함께 "다음 역에서 내리세요" 알림을 보냅니다. 상단 알림에는 남은 시간이 초 단위로 줄어듭니다 |

## 사용 방법

1. 첫 화면에서 노선을 고르거나 역 이름을 검색해 역을 엽니다. 자주 쓰는 역은 ☆를 눌러 즐겨찾기에 넣으세요.
2. 정보판에서 타려는 열차를 누르고 **탑승 시작**을 누릅니다(위치, 알림, 신체 활동 권한을 허용해야 합니다).
3. 탑승 화면에서 내릴 역을 누르면 하차 알림이 걸립니다. 다음 역 또는 하차역 도착 예정 시각(HH:mm:ss)과 남은 시간이 보입니다.
4. 역이 틀리면 **현재 역 고치기**로 알려 주세요. 같은 구간을 여러 번 탈수록 구간 시간과 역별 무선 신호가 쌓여 정확해집니다.

> 안드로이드는 앱의 Wi-Fi 스캔을 2분에 4회로 제한합니다. 더 자주 스캔하려면 **개발자 옵션 → Wi-Fi 스캔 제한**을 끄세요.
> 기지국·Wi-Fi 정보를 읽으려면 위치 서비스(GPS 설정)가 켜져 있어야 합니다. 수집한 신호는 폰 안에만 저장합니다.

> Galaxy에서 화면을 끈 채로 오래 쓰려면 **설정 → 애플리케이션 → 지하철 도착 예측 → 배터리 → 제한 없음**으로 바꾸세요.
> 바꾸지 않으면 One UI의 절전 기능이 센서 수집을 멈출 수 있습니다.

## 데이터

`app/src/main/assets/lines/` 폴더에 노선 파일이 있습니다. 형식은 [`LineParser.kt`](core/src/main/kotlin/com/subwayeta/core/model/LineParser.kt) 맨 위 설명을 참고하세요.

| 파일 | 노선 | 역 수 | 비고 |
|---|---|---|---|
| `line1_gyeongin.txt` | 1호선 소요산–인천 | 62 | 경원선 + 서울 지하 구간 + 경인선 |
| `line1_gyeongbu.txt` | 1호선 소요산–신창 | 77 | 경원선 + 서울 지하 구간 + 경부선. 소요산–구로는 경인 방면과 같은 역 id |
| `line2.txt` | 2호선 | 43 | 순환선. 내선순환(시계 방향)과 외선순환 중 선택 |
| `line7.txt` | 7호선 장암–석남 | 53 | |
| `line9.txt` | 9호선 개화–중앙보훈병원 | 38 | **급행** 지원. 급행 정차역끼리 고르면 급행 경로로 예측 |

- 1호선은 갈라지는 노선이라 방면별로 두 개로 나눴습니다. 인천행이면 "소요산–인천", 수원·천안행이면 "소요산–신창"을 고르세요.
- 좌표, 구간 시간, 정차 시간은 **학습 전에 쓰는 추정 초깃값**입니다. 1·7·9호선 구간 시간은 역 사이 직선거리로 계산했습니다(최고 속도 1호선 90km/h, 7·9호선 80km/h, 가감속 0.9m/s²).
  급행 구간은 통과하는 역마다 15초씩 줄인 값을 씁니다. 공공데이터포털이나 서울 열린데이터광장의 공식 시간표 값으로 바꾸면 처음 몇 번의 이동부터 더 정확합니다.
- 같은 형식의 파일을 `assets/lines/`에 추가하면 노선 선택 목록에 바로 나타납니다.

## 임계값 튜닝

센서 임계값([`MotionConfig`](core/src/main/kotlin/com/subwayeta/core/motion/MotionClassifier.kt))은 합성 신호로 맞춘 값입니다. 실제 열차에서 기록을 남기고 조정하는 것을 권합니다.
이동할 때마다 1초 단위 특징값과 출발/정차 이벤트가 CSV로 저장됩니다.

```bash
adb pull /sdcard/Android/data/com.subwayeta.app/files/logs
```

## 구조

```
core/   순수 Kotlin(JVM) 엔진. 안드로이드 없이 단위 테스트 가능
  model/   노선, 경로, 노선 파일 파서
  motion/  MotionClassifier: 센서 → 출발/정차 이벤트
  engine/  TripTracker(현재 역 추적), Predictor(초 단위 예측), TravelStats(학습), TripSession(묶음)
app/    안드로이드 앱 (Jetpack Compose)
  tracking/TrackingService  포그라운드 서비스: 센서, GPS, 알림, 학습값 저장
  ui/                       출발/도착 선택 화면, 추적 화면
```

## 빌드

```bash
./gradlew :core:test          # 엔진 테스트 (합성 센서 신호로 ±1초 정밀도 검증 포함)
./gradlew :app:assembleDebug  # APK → app/build/outputs/apk/debug/
```

GitHub Actions(`.github/workflows/android.yml`)가 푸시할 때마다 테스트와 APK 빌드를 실행합니다. 빌드된 APK는 실행 결과 페이지의 **Artifacts**에서 내려받을 수 있습니다.

## 한계와 다음 단계

- 1호선 급행(경인·경부 급행, 특급)은 아직 정차역 데이터가 없어 일반 열차로만 예측합니다. 급행을 타면 통과한 역을 "정차를 놓친 것"으로 처리해 일부 보정되지만, 정확도는 떨어집니다.
- 1호선 광명·서동탄 지선, 2호선 성수·신정지선, 노선 간 환승은 아직 지원하지 않습니다.
- 도착 정보판의 운행 패턴은 **추정 배차 간격**입니다. 실제 열차와 몇 분씩 어긋날 수 있으니, 공식 시간표(공공데이터포털)를 받아 노선 파일의 `!` 행으로 바꾸면 정확해집니다.
- 무선 신호 보정은 같은 역을 한 번 이상 지나며 학습해야 동작합니다(역 이름이 들어간 Wi-Fi는 예외).
